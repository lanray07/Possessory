# Cloudflare receipt verifier

This Worker preserves the Android `SignedLicense` format: base64url UTF-8 JSON and an RSA PKCS#1 v1.5 SHA-256 signature. It accepts only `userId` and `receiptId`, calls Amazon RVS, requires the configured one-time entitlement, and rejects unidentified transactions in production. Amazon-verified LAT and publishing-test receipts are accepted through production RVS; App Tester receipts still use only sandbox RVS. Sandbox responses always carry `environment=sandbox` and use a separate private signing key. Future cancellation dates also cap an active license's validity.

Install with `npm ci`, run `npm test`, and validate bundling with `npm run check`. Wrangler is pinned in package-lock.json. Deploy with `npm run deploy:production` and `npm run deploy:sandbox`. These names were checked as absent before the initial creation; do not overwrite another service.

The two Workers have their own rate-limit namespaces. The broad per-IP ceiling is 120/minute and a SHA-256 hash of each user/receipt pair is limited to 10/minute. Cloudflare's counters are approximate and local to a Cloudflare location, not a strict global quota. No inventory content or durable customer database is accepted. Incoming bodies are capped at 4096 bytes, upstream JSON at 65536 bytes, and upstream requests time out after 10 seconds with redirects forbidden. Errors omit upstream URLs and secret values.

Application observability/logpush and Wrangler usage metrics are disabled. Never enable outbound URL tracing: Amazon puts its developer secret in the RVS path. Cloudflare still processes network metadata for operating/security purposes; update the owner-reviewed privacy disclosures before enabling public purchases. No paid plan or account upgrade is requested by these scripts. Verify actual account usage/limits in Cloudflare; no unlimited/free-capacity promise is made.

Create an owner-only directory outside the repository at `~/.android/possessory-receipt-verifier`. Store the existing Amazon Shared Key in `amazon-shared-secret.txt` there. Do not put it in chat, `.dev.vars`, Git, or an APK. `node configure-secrets.mjs` creates separate RSA-3072 PKCS8 license keys if absent, preserves existing keys, and uploads the two secret bindings per Worker through Wrangler stdin. It refuses to generate a replacement if the deployed Worker already has a signing-key binding. It writes only public endpoint/SPKI key configuration to `android-public-config.json` and a private-directory copy named `public-build-config.json`. Preserve the private keys securely; changing a deployed key invalidates previously issued licenses and requires coordinating the Android trust key.

The current endpoints are `https://possessory-receipts-production.lanraybanks.workers.dev/verify` and `https://possessory-receipts-sandbox.lanraybanks.workers.dev/verify`. Run `python -X utf8 tools/check_cloudflare.py` from the repository root for public health/invalid-receipt/input-contract probes. `tools/build_cloudflare_candidate.ps1` builds the Amazon release with the checked-in public trust configuration; `-IncludeIapQa` additionally creates an isolated, debuggable `.iapqa` App Tester package. Never submit the QA or review APK. The new configured release is kept under a distinct artifact name so the earlier reviewer-pack hashes remain valid.

Use the production endpoint/public key for `POSSESSORY_VERIFIER_URL` and `POSSESSORY_LICENSE_PUBLIC_KEY`; use the separate sandbox pair for the `POSSESSORY_SANDBOX_*` variables. Nothing in the `.review` APK grants an Amazon entitlement. The distinct Cloudflare release candidate has been rebuilt and signed with the existing APK key.
