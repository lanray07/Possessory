# Fire billing checks and cancellation correction

On 28 October 2026, physical App Tester checks on the KFTRWI Fire tablet exposed a cancellation defect in 0.3.3. The App Tester transaction was visibly CANCELED, while a fresh request to the deployed sandbox verifier still returned an active signed claim for that same test receipt. The app accepted that claim and retained Premium. The revocation device probe failed after 60 seconds; inspection confirmed the cached claim remained active. No customer identifiers or receipt tokens are included in this report.

Version 0.3.4 treats an SDK cancellation as an immediate denial of access. It records the cancelled user/receipt pair in memory, clears the matching cached entitlement, and prevents verification for that receipt from granting Premium. Cancelling an old receipt does not clear a different, newly verified receipt. A late product-price callback does not replace the revoked status. Positive access still requires the Cloudflare verifier's signed Amazon-verified claim.

The original cancelled-transaction probe passed after the correction and confirmed that cached entitlement storage was empty. A fresh purchase through the real App Tester Get Item / order-complete dialogs then passed signature verification and explicit restore. Offline cached access and offline expiry also passed for the new entitlement. This was a sandbox transaction, with no real charge; it is not production/LAT certification.

The final candidate also checks cancellation/account changes after the suspended DataStore save. Six final device scenarios passed against the packaged APK: cancellation, fresh purchase/restore, cached offline restart, expired offline restart, actual account switch away and return. The account-switch setup was refreshed after expiry had removed the cached entitlement. Final release lint has zero errors; unit tests passed before the final Amazon-only timing guard, which was then exercised by the device checks. Exact counts, raw logs and APK hashes are recorded in artifacts/billing-checks-0.3.4/summary.json.

Earlier in this run, actual App Tester user switching from User 1 to User 2 removed cached access, and switching back restored it. The current 0.3.3 localized review APK passed 175 physical-device navigation captures, including nineteen locales and English/German/Arabic portrait and 200% font settings. Eight fresh English marketing images include actual native receipt extraction, PDF preview, typed voice fallback and disconnected inventory. Capture provenance identifies their original build; they are not silently relabelled as 0.3.4 captures.

One initial store-data timeout cleared after restarting App Tester to reload the temporary catalogue. One account-return run and one marketing run were accidentally overlapped; those results were discarded and both checks passed when rerun sequentially. The cancellation failure was a separate confirmed app defect, not dismissed as test setup.

Remaining Amazon gates: production/LAT receipt flows, completing localized wording and production bundling, final localized marketing assets, browser/console access, and operator privacy/export declarations. Independent human review is waived and is not a release gate. The built-in browser helper still fails to initialize with a missing kernel-assets path.

The signed production candidate is artifacts/Possessory-amazon-0.3.4-release-signed.apk (English-only). Its DEX contains the production verifier URL/public key and excludes the sandbox URL/key. Eight visually checked English marketing exports are in artifacts/Possessory-0.3.3-eight-marketing-screenshots-ENGLISH.zip. Approval covers these English assets only, with independent human review waived; it does not approve the application release or other locale assets. All 175 current review captures are indexed in artifacts/reviewer-captures-0.3.3/manifest.json. Neither the review nor App Tester APK is a store binary.

Cleanup completed: the App Tester catalogue was restored byte-for-byte, User 1/US remained selected, global sandbox mode was cleared, Wi-Fi/font/rotation/keep-awake settings were restored, and the isolated QA packages were uninstalled. Only Possessory test transactions were cancelled or repurchased. Production inventory and volume were untouched.

Amazon documents App Tester's account and transaction controls in its [App Tester guide](https://developer.amazon.com/docs/in-app-purchasing/iap-app-tester-user-guide.html). Test-only controls and receipts must not be represented as live-store validation.
